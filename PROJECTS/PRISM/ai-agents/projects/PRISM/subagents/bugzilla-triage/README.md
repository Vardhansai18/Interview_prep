# 📁 bugzilla-triage — BIG-IP Bug Triage Agent

## Description

The **bugzilla-triage** agent is an automated BIG-IP bug triage assistant. It fetches bug details from the F5 internal Bugzilla instance, detects duplicate bugs, validates component assignments against the source-to-component mapping CSV, checks whether reported behavior is RFC-compliant or a genuine defect, performs initial root cause analysis on mcpd backtraces, identifies workarounds, and surfaces additional data needed from reporters.

## 🌐 Supported Input Modes

| Mode | Input | What the agent does |
|------|-------|---------------------|
| **Mode 1: Bug ID** | Bugzilla bug number (e.g., `1234567`) | Full triage: fetch, dedup, component validation, RFC check, root cause analysis, workaround |
| **Mode 2: Backtrace / Error** | Core file backtrace or log error message | Parse frames, map to mcpd components, search Bugzilla for matching bugs |

## 🚀 Quick Start

Triage Bugzilla bug <BUG_ID>
```

```

```

```

## 🔄 Agent Workflow

The agent follows a 7-step triage workflow:

1. **Authenticate** — Verify `BUGZILLA_API_KEY` env var or prompt the user
2. **Fetch Bug Data** — Retrieve full bug details via Bugzilla XML API
3. **Duplicate Detection** — Run 3-pass search (summary + full-text + crash signature), evaluate candidates
4. **Component Validation** — Map backtrace source paths to `shared/component_mappings/bigip_component_map.csv`, flag mismatches
5. **RFC / Standard Compliance** — Identify governing RFC(s), apply requirement-level analysis, issue verdict
6. **Root Cause Analysis** — Read mcpd source files, analyze backtrace, assess crash pattern (only for confirmed defects)
7. **Workaround Identification** — Suggest configuration/operational mitigations, search Ask F5 Knowledge Base

## 📂 Skills Reference

### bugzilla-api.SKILL.md
- Bugzilla authentication via `BUGZILLA_API_KEY` environment variable
- Bug fetch URL patterns (`show_bug.cgi` XML format)
- Search URL patterns: summary search, full-text search, crash signature search
- CSV output parsing rules
- Duplicate detection strategy (3-pass search + candidate evaluation)
- Common Bugzilla search patterns for mcpd function names, error messages, and versions

### rfc-compliance.SKILL.md
- Protocol-to-RFC mapping table for all major BIG-IP protocol areas (OCSP, LDAP, TLS, HTTP, X.509, BGP, OSPF, DNS, RADIUS, TACACS+)
- RFC requirement levels: MUST / SHOULD / MAY and their compliance obligations
- Detailed rules for the most common bug areas: OCSP caching, LDAP Abandon, TLS client cert, X.509 hostname verification, HTTP session handling
- Third-party behavior analysis (LDAP server, OCSP responder, Apache/OpenSSL, CA/PKI)
- Five-verdict output format with RFC citations

### component-mapping.SKILL.md
- CSV format and location: `shared/component_mappings/bigip_component_map.csv`
- Key mcpd path → Bugzilla component mappings
- Complete mcpd subdirectory reference table with purpose and key filenames
- Source path extraction rules for both F5 custom and GDB standard backtrace formats
- Longest-prefix-match algorithm for component lookup
- Validation procedure and output format

## 🔍 Backtrace Format Support

The agent auto-detects and parses two backtrace formats:

| Format | Example line | Source |
|--------|-------------|--------|
| **F5 Custom** | `[ 04 ] libmcpdcommon.so MCPConnection::sendMessage() ( MCPConnection.cpp:1267 )` | F5 core dump tool |
| **GDB Standard** | `#2 audit_remove_ltcfg_passwords (...) at authz/Audit.cpp:333` | GDB / LLDB |

## 🔒 Security Constraints

- **READ-ONLY**: The agent NEVER modifies bugs in Bugzilla
- **API KEY**: Never logged, echoed, printed, or stored in any file
- All Bugzilla access is authenticated via `BUGZILLA_API_KEY` environment variable
